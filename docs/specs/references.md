
# References

The following resources were consulted during the development of the Archeology REST API.

## Validation

- [Valicomb — GitHub](https://github.com/frostybee/valicomb) — Input validation library used to define validation rules.

## Composite Resources

- [Guzzle Documentation](https://docs.guzzlephp.org/en/stable/) — HTTP client documentation for external web services.
- [Sub-Collection Implementation Guide](https://ws.frostybee.dev/implementation/common/sub-collection/) — Implementation of related API resources.

## OpenAPI and YAML

- [OpenAPI Implementation Guide](https://ws.frostybee.dev/implementation/common/openapi/) — Documenting API endpoints using OpenAPI.
- [YAML Implementation Guide](https://ws.frostybee.dev/implementation/common/yaml/) — Writing YAML specifications.
- [OpenAPI Specification 3.2.0](https://spec.openapis.org/oas/v3.2.0.html) — Official OpenAPI specification.
- [Swagger Documentation](https://swagger.io/docs/) — OpenAPI documentation tools and syntax.

## Result Pattern

- [Result Pattern Guide](https://ws.frostybee.dev/implementation/input-validation/result-pattern/) — Handling operation results and validation errors.

## PHP Documentation

- [PHPDocumentor: Basic Syntax](https://docs.phpdoc.org/guide/references/phpdoc/basic-syntax.html) — Writing PHPDoc documentation for classes and methods.

## Slim Framework

- [Slim Framework](https://www.slimframework.com/) — Official documentation for the Slim PHP framework.

## Error Handling and HTTP Status Codes

- [Using HTTP Exceptions in Slim Framework](http://ws.frostybee.dev/implementation/error-handling/slim-http-exceptions/) — Handling HTTP errors and exceptions in Slim applications.
- [HTTP Status Codes](https://ws.frostybee.dev/lectures/www/status-codes/) — Understanding HTTP response status codes and their appropriate usage in REST APIs.
